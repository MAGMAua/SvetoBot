# svetobot — мониторинг электроснабжения

Docker-контейнер, который непрерывно пингует заданные адреса, определяет наличие
электричества на объектах (дом, работа) и присылает уведомления в Telegram при смене
состояния. Журнал и статистика хранятся в SQLite, управление — командами бота.

Как принимается решение:

1. Опрос идёт **каждые 10 секунд** — на сервере нет ограничений по батарее,
   поэтому отключение видно почти сразу.
2. Объект считается под напряжением, если отвечает **хотя бы один** из его адресов.
3. Отключение подтверждается в два этапа. После `fail_threshold` = 3 неудачных
   проверок подряд (~30 секунд) приходит тихое «🟡 Нет связи». «🔴 Света нет» со
   звуком приходит, только если объект молчит `outage_confirm_after` = 300 секунд.
   Если связь вернулась раньше — тихое «Связь восстановлена, это был сбой связи».
   Так пропадание интернета у провайдера на объекте не выдаётся за отключение света.
   Возврат света подтверждается после `ok_threshold` = 2 удачных проверок (~20 секунд).
4. Пропадания, не ставшие отключением, записываются как кратковременные
   сбои и доступны по кнопке «⚡ Сбои».
5. Если связь потерял сам сервер, опрос приостанавливается, статусы объектов
   сохраняются, и через 2 минуты приходит предупреждение об этом.

Момент смены датируется **первым несовпадением**, а не моментом подтверждения,
поэтому длительность отключений в журнале точная.

## Быстрый старт

```bash
git clone <репозиторий> svetobot && cd svetobot   # или распакуйте архив

cp .env.example .env
cp config/config.example.json config/config.json

nano .env                 # токен бота и ID чатов
nano config/config.json   # адреса объектов

docker compose up -d --build
docker compose logs -f
```

### .env

| Переменная          | Назначение                                                        |
|---------------------|-------------------------------------------------------------------|
| `TELEGRAM_TOKEN`    | Токен от [@BotFather](https://t.me/BotFather)                      |
| `TELEGRAM_CHAT_IDS` | ID чатов через запятую. Свой ID — у @userinfobot, ID группы с «-»  |
| `TZ`                | Часовой пояс для времени в сообщениях, по умолчанию Europe/Moscow  |
| `LOG_LEVEL`         | `INFO` или `DEBUG`                                                 |

Чаты из `TELEGRAM_CHAT_IDS` — одновременно и список получателей уведомлений,
и белый список: команды от остальных игнорируются.

### config/config.json

```json
{
  "poll_interval": 10,
  "fail_threshold": 3,
  "ok_threshold": 2,
  "outage_confirm_after": 300,
  "internet_alert_after": 120,
  "network": {
    "internet_hosts": ["77.88.8.8", "8.8.8.8"],
    "ping_count": 1,
    "ping_timeout": 2,
    "ping_deadline": 3
  },
  "targets": [
    { "id": "home", "name": "Дом",    "emoji": "🏠", "hosts": ["217.199.235.61"] },
    { "id": "work", "name": "Работа", "emoji": "🏢", "hosts": ["46.162.18.93", "78.31.178.137"] }
  ]
}
```

- `poll_interval` — период опроса в секундах.
- `fail_threshold` — сколько неудачных проверок подряд означают отключение.
- `ok_threshold` — сколько удачных подряд означают возврат света.
- `outage_confirm_after` — сколько секунд объект должен молчать, чтобы пришло
  «Света нет». До этого — только тихое «Нет связи». `0` — сообщать об отключении
  сразу после `fail_threshold`.
- `internet_alert_after` — через сколько секунд без интернета предупредить о проблеме сервера.
- `network.internet_hosts` — адреса для проверки связи у самого сервера.
- `network.ping_count`, `ping_timeout`, `ping_deadline` — параметры `ping`:
  число пакетов, ожидание ответа и общий лимит на одну проверку, в секундах.
- `hosts` — адреса объекта; достаточно ответа одного, чтобы считать, что свет есть.
- Объектов может быть сколько угодно: добавьте ещё блок в `targets` со своим `id`.

«Нет связи» приходит через `poll_interval × fail_threshold` (~30 секунд),
«Света нет» — через `outage_confirm_after` (5 минут). Если интернет на объекте
часто пропадает дольше 5 минут, увеличьте `outage_confirm_after`; если нужен
более быстрый сигнал — уменьшите его, но тогда сбои связи чаще будут выглядеть
как отключения.

Изменения в конфиге применяются после `docker compose restart svetobot`.

## Управление ботом

После `/start` внизу чата появляется постоянная клавиатура:

| Кнопка            | Что делает                                                        |
|-------------------|-------------------------------------------------------------------|
| 💡 Статус         | Текущее состояние, длительность, время последней проверки         |
| 🔄 Проверить      | Внеочередная проверка прямо сейчас                                |
| 📜 Журнал         | Последние 15 событий                                              |
| ⚡ Сбои           | Кратковременные пропадания, не ставшие отключением                |
| 📊 Статистика     | Отключения и время без света; период — кнопками под сообщением: сутки, неделя, месяц |
| 🔕 Тихий режим    | Уведомления о смене статуса без звука на 30 мин – 24 ч; там же «Включить звук» |

Команды тоже работают и позволяют задать число вручную:
`/status`, `/check`, `/log [N]`, `/flaps [N]`, `/stats [дней]`, `/mute [минут]`,
`/unmute`, `/help`.

Пример уведомления:

```
🔴 Света нет · 🏢 Работа
Пропал сегодня в 15:22
До этого свет был 6 ч 40 мин
```

```
🟢 Свет есть · 🏢 Работа
Появился сегодня в 21:40
Света не было 6 ч 18 мин
```

Если интернет пропал у самого сервера, приходит «⚠️ Сервер без интернета»
(если Telegram при этом доступен), а после восстановления — «✅ Сервер снова
на связи» с длительностью перерыва. Кратковременные сбои связи с объектом
уведомлений не дают, их видно по кнопке «⚡ Сбои».

## Данные

- `data/svetobot.db` — SQLite: текущее состояние, журнал событий, настройки.
  Каталог смонтирован наружу, поэтому история переживает пересборку образа.
- Выгрузить журнал в CSV:

```bash
docker compose exec svetobot python -c "
import sqlite3, csv, sys
rows = sqlite3.connect('/data/svetobot.db').execute(
    'SELECT ts, target_id, status, duration FROM events ORDER BY ts')
w = csv.writer(sys.stdout); w.writerow(['ts','target','status','duration']); w.writerows(rows)
" > svet.csv
```

## Технические заметки

- Для ICMP-ping контейнеру нужна capability `NET_RAW` — она уже указана в
  `docker-compose.yml` и входит в набор Docker по умолчанию.
- Если на сервере ICMP закрыт наружу, ping работать не будет. Тогда проверку можно
  заменить на TCP-подключение к известному порту объекта — правится в `app/checker.py`,
  функция `ping`.
- Контейнер не открывает портов: бот работает через long polling, входящие соединения
  не нужны, webhook и белый IP не требуются.
- Потребление: около 40 МБ RAM. Трафик при опросе раз в 10 секунд — порядка
  нескольких мегабайт в месяц, нагрузка на CPU незаметная.
- Факт проверки пишется в БД не чаще раза в минуту, поэтому частый опрос
  не изнашивает диск: в базу попадают только смены статуса и сбои.

## Структура

```
Dockerfile
docker-compose.yml
requirements.txt
.env.example
config/config.example.json
app/
  main.py      — запуск, конфигурация
  monitor.py   — цикл опроса, подтверждение смен, уведомления
  checker.py   — ping и разовая проверка объекта
  storage.py   — SQLite: состояние, журнал, настройки
  bot.py       — команды Telegram
  tg.py        — клиент Bot API
  util.py      — форматирование времени
```
